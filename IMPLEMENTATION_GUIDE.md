# nConnect - Service Marketplace Platform Implementation Guide

## Project Overview
nConnect is a **digital-only service marketplace platform** built with Flutter and Supabase that enables professionals to list and deliver online services while customers can discover and order them.

### Core Philosophy
- **Digital-Only**: All services are delivered online (no physical goods or in-person meetups)
- **Strict RBAC**: Three completely isolated user roles (Admin, Professional, Customer)
- **Escrow-Based Payments**: All payments held in escrow until admin approval
- **Server-Side Fee Deduction**: Platform profit percentage configured globally and applied automatically

---

## Architecture & Tech Stack

### Frontend
- **Framework**: Flutter (Dart)
- **Target Platform**: Web (primary), with mobile support ready

## Database Schema (Supabase PostgreSQL)

### Key Tables

**1. users**
- `uid` (PK, FK to auth.users)
- `full_name`, `email`, `phone_number`
- `primary_role` ('Admin', 'Professional', 'Customer')
- `wallet_balance`, `is_verified`, `is_suspended`
- RLS: Users can only read/update their own row

**2. categories** (Admin-managed)
- `id` (UUID PK)
- `name` (UNIQUE)
- `description`, `icon_url`
- `created_by` (FK to users)
- RLS: Anyone can read; only admins can write

**3. services** (Professional-created)
- `id` (UUID PK)
- `provider_id` (FK to users)
- `category_id` (FK to categories)
- `title`, `description`
- `delivery_time_days`, `max_revisions`
- `status` ('active', 'paused', 'archived')
- `rating_avg`, `total_orders`
- RLS: Professionals can CRUD own; customers can read active only

**4. service_packages** (3-tier pricing)
- `id` (UUID PK)
- `service_id` (FK to services)
- `package_type` ('Basic', 'Standard', 'Premium')
- `price`, `description`, `features` (JSONB)
- RLS: Inherit from service

**5. service_addons** (Optional extras)
- `id` (UUID PK)
- `service_id` (FK to services)
- `title`, `price`
- RLS: Inherit from service

**6. orders** (Service requests)
- `id` (UUID PK)
- `customer_id`, `professional_id` (FK to users)
- `service_id` (FK to services)
- `package_type`, `base_price`, `platform_fee_amount`, `total_amount`
- `status` ('pending', 'accepted', 'in_progress', 'submitted', 'confirmed', 'completed', 'cancelled')
- `created_at`, `delivery_deadline`
- RLS: Users can read own orders; professionals can update status

**7. escrow_payments** (Payment hold mechanism)
- `id` (UUID PK)
- `order_id` (FK to orders)
- `customer_id`, `professional_id` (FK to users)
- `amount`, `platform_fee_amount`, `professional_amount`
- `status` ('held', 'released', 'refunded')
- `created_at`, `released_at`
- `admin_notes`
- RLS: Only admins can modify; users can read own

**8. transactions** (Audit log)
- `id` (UUID PK)
- `user_id` (FK to users)
- `type` ('order', 'payment', 'withdrawal', 'refund')
- `amount`, `status`
- `description`, `related_order_id`
- `created_at`
- RLS: Users can read own; admins can read all

**9. withdrawal_requests** (Payout requests)
- `id` (UUID PK)
- `professional_id` (FK to users)
- `amount`, `status` ('pending', 'approved', 'rejected', 'completed')
- `requested_at`, `approved_at`, `completed_at`
- `admin_notes`
- RLS: Professionals create own; admins approve

**10. task_submissions** (Work delivery & revisions)
- `id` (UUID PK)
- `order_id` (FK to orders)
- `professional_id` (FK to users)
- `description`, `attachmentUrls` (array)
- `status` ('submitted', 'revision_requested', 'confirmed')
- `revisionNotes`, `revisionNumber`
- `submitted_at`
- RLS: Professionals submit; customers review

**11. reviews** (Ratings & feedback)
- `id` (UUID PK)
- `order_id` (FK to orders)
- `reviewer_id`, `reviewee_id` (FK to users)
- `rating` (1-5), `comment`
- `review_type` ('service', 'professional', 'customer')
- `created_at`
- RLS: Reviewers can write once per order

**12. platform_settings** (Admin configuration)
- `id` (UUID PK)
- `platform_fee_percentage` (default: 15%)
- `min_withdrawal_amount`, `max_order_value`
- `updated_by` (FK to users)
- `updated_at`
- RLS: Only admins can modify

**13. audit_logs** (Compliance)
- `id` (UUID PK)
- `admin_id` (FK to users)
- `action`, `table_name`, `record_id`
- `changes` (JSONB)
- `created_at`
- RLS: Only admins can write; admins can read all

## Payment & Escrow Flow

### Order Lifecycle
1. **Customer places order** → Order created with status='pending'
2. **Payment captured** → Escrow payment created with status='held'
3. **Professional accepts** → Order status becomes 'accepted'
4. **Work in progress** → Order status becomes 'in_progress'
5. **Professional submits** → Task submission created; order status='submitted'
6. **Customer reviews** → Reviews submission/requests revisions
7. **Customer confirms** → Order status='confirmed'; awaits admin approval
8. **Admin approves** → Escrow released to professional; transaction created
9. **Withdrawal** → Professional creates withdrawal request (auto-approved for released funds)

### Fee Calculation (Server-Side)
```
base_price = Sum of (selected package price + selected addon prices)
platform_fee = base_price * (platform_fee_percentage / 100)
total_amount = base_price + platform_fee

escrow_payment.amount = total_amount
escrow_payment.platform_fee_amount = platform_fee
escrow_payment.professional_amount = base_price
```

**Key Constraint**: Professional never receives full amount directly. Admin must explicitly approve release of funds to professional's wallet.

## Role-Based Access Control (RBAC)

### Admin Role
- **Separate Application**: Completely isolated UI/routing (`/admin/*`)
- **Capabilities**:
  - Set global platform fee percentage (platform_settings)
  - Manage categories (CRUD)
  - Approve service listings
  - Monitor all escrow payments
  - Approve/reject fund releases
  - Suspend users
  - View audit logs
  - Generate financial reports
- **Database Access**: All tables via RLS admin policies
- **Visibility**: Never appears in role selection for customers/professionals

### Professional Role
- **Dashboard**: `/professional-dashboard`
- **Capabilities**:
  - Create/edit/pause services
  - Define packages (Basic/Standard/Premium) and add-ons
  - Accept/reject orders
  - Submit work & revisions
  - View earnings/orders
  - Request fund withdrawals
  - View customer reviews
- **Database Access**: Own services, owned orders, own transactions
- **Service Visibility**: Cannot see own services when viewing as Customer (RLS enforces this)

### Customer Role
- **Dashboard**: `/customer-dashboard`
- **Capabilities**:
  - Browse services (excluding own if also professional)
  - Filter by category, price, rating
  - Place orders with package/addon selection
  - Track order progress
  - Submit work confirmations
  - Request revisions
  - Leave reviews
  - View transaction history
- **Database Access**: Browse services; own orders; own reviews
- **Service Visibility**: Cannot see services by self; other professionals' only

### Role Switching (Without Re-login)
- **Enabled**: Single user can be both Professional AND Customer
- **Mechanism**: Update `users.primary_role` in database
- **Limitation**: Cannot be Admin (separate account creation)
- **UI**: Role selection screen with card-based interface
- **Location**: Via "↔️" button on dashboards

## Security & Compliance

### Row-Level Security (RLS)
All tables enforce RLS at database level. Example policies:

```sql
-- Users table: Only self-read/update
CREATE POLICY users_select_own ON users
  FOR SELECT USING (auth.uid() = uid);

CREATE POLICY users_update_own ON users
  FOR UPDATE USING (auth.uid() = uid);

-- Services table: Professionals create own; customers read active
CREATE POLICY services_select_active ON services
  FOR SELECT USING (status = 'active' OR provider_id = auth.uid());

CREATE POLICY services_insert_own ON services
  FOR INSERT WITH CHECK (provider_id = auth.uid() AND current_setting('role') = 'Professional');

-- Orders table: Users see own; professionals update own
CREATE POLICY orders_select_own ON orders
  FOR SELECT USING (
    customer_id = auth.uid() OR professional_id = auth.uid()
  );

-- Escrow payments: Only admins modify
CREATE POLICY escrow_admin_only ON escrow_payments
  FOR UPDATE USING (
    current_setting('role') = 'Admin'
  );
```

### Audit Trail
- All admin actions logged in `audit_logs` table
- Fund releases tracked with admin_notes
- Transaction history immutable after creation
- Compliance-ready for financial audits
